The Datagraph is part of the [DataHub](/product-guide/datahub/overview). You can describe how your Datasources relate and reuse that trusted data in your Workflows.

<Warning>
  The Datagraph is in beta. Its pages and options can still change. Talk to your Technical Account Manager before you rely on it in a live Workflow.
</Warning>

## Why Use the Datagraph?

Each Datasource holds one set of data — products, stores, purchases, or customers. On its own, a Datasource cannot answer a question that needs two sets of data at once.

The Datagraph links Datasources. Your data team can prepare reusable Objects, such as “top five products bought by this person”. Any Workflow can reuse them.

<Tip>
  You do not have to build the Datagraph yourself. It is usually set up once by your data team or your Reelevant Technical Account Manager, then reused by everyone.
</Tip>

## Where to Find It

Open **DataHub** in the sidebar, then choose **Datagraph**. Use these pages to explore the model and its reusable Objects:

| Page | What it is for |
|------|----------------|
| **Schema** | Edit the model in **Visual** or explore it in **Diagram**, **Relations**, and **Datasources**. |
| **Objects** | Reusable data results built on the model, ready to use in Workflows. |
| **Object families** | Sets of Objects with the same output fields, so a Workflow can use different members. |

On **Objects**, choose **CREATE OBJECT** to add an Object. The list shows **No objects yet** until you create one.

In **Object families**, select **Create family** to define shared output fields.

On **Schema**, use **Visual** to edit tables. Select **Diagram**, **Relations**, or **Datasources** to explore the model.

![Schema page Visual view for a property listings model, showing five SeLoger tables and the selected users table's columns](/images/datahub/datagraph-seloger-schema.png)

The **Relations** tab shows the links between tables and the fields they use.

![Relations tab of the Datagraph Schema page, showing links from recommendations to users and listings](/images/datahub/datagraph-seloger-schema-relations.png)

## Exploring the Schema

The Schema page includes views for exploring the model and checking its links.

1. Open **DataHub → Datagraph → Schema**.
2. Select the **Diagram** tab to see each Datasource as a box, with lines showing how they are linked.
3. Drag the diagram to move around, and use the zoom buttons to get closer.
4. Open the **Relations** tab to review each link one by one.
5. Open the **Datasources** tab to list the Datasources used in the model, with their fields.

![Diagram tab of the Datagraph Schema page, showing five linked property Datasources as boxes connected by lines](/images/datahub/datagraph-seloger-explorer.png)

<Info>
  The **Diagram**, **Relations**, and **Datasources** tabs show the Draft version when one exists. Otherwise, they show the Published version.
</Info>

On the **Relations** tab, each link shows a **Join match** percentage. It tells you how well the values on both sides overlap in your data.

![Relations tab of the Datagraph Schema page, listing five links with their join match percentages](/images/datahub/datagraph-seloger-relations.png)

| Filter | What it shows |
|--------|---------------|
| **All** | Every link in the model. |
| **Good** | Links where the values overlap well. |
| **Weak** | Links with a low overlap — worth a look with your data team. |
| **Invalid** | Links that could not be checked at all. |

<Warning>
  A weak or invalid link usually means the two Datasources do not share the same identifiers. Personalisation built on that link may return no result, so raise it with your data team before you use it in a Workflow.
</Warning>

## Draft and Published Versions

The **Schema** page shows a **Draft** or **Published** status badge. Each Object also has its own version.

| Status | Meaning |
|--------|---------|
| **Draft** | Work in progress. Only visible inside the Datagraph pages. |
| **Published** (or **Live**) | The version Workflows actually use. |
| **Inactive** | A previously published version, kept for history. |

Nothing you see in a Draft affects your live personalisation until someone publishes it.

![Datagraph Objects listing with Name, Status, and Last update columns](/images/datahub/datagraph-seloger-entities.png)

## What Objects Can Answer

An Object answers one question about one person, one product, or one area. Your data team writes it once, and every Workflow can reuse it.

Here are typical examples for a property listings account:

| Object | The question it answers |
|--------|-------------------------|
| **Listings matching a user search** | Which listings sit in the area this person is searching, within their budget? |
| **Listings with a recent price drop** | Which listings in an area just became cheaper, biggest drop first? |
| **Market prices in the user area** | What is the median price per square metre and the trend where this person is searching? |
| **Recommended listings for a user** | Which listings does our recommendation data suggest for this person? |
| **Editorial content for an area** | Which guides and market articles are published for this area? |

The same patterns work for other businesses. For example, a retail account might need to show the last items a person bought. It might also show stock in their favourite store or best sellers in their preferred category.

<Tip>
  Describe the question you need in plain words, with the data it should return. Your data team turns it into an Object, then you pick it in your Workflow.
</Tip>

The Object editor includes **Object name** and **Edited object** fields, plus **INPUT / OUTPUT** and **VERSIONS** panels. Open **PREVIEW & RESULTS** to check the returned values.

![Datagraph Object editor with Object name and Edited object fields, INPUT / OUTPUT and VERSIONS side panels, and the collapsed PREVIEW & RESULTS panel](/images/datahub/datagraph-seloger-entity-editor.png)

The **INPUT / OUTPUT** panel lists each parameter and the returned fields, with output types shown as **Text**, **Number**, or **Image URL**.

![INPUT / OUTPUT panel showing the user_id parameter and returned fields with Text, Number, and Image URL types](/images/datahub/datagraph-seloger-entity-input-output.png)

## Using an Object in a Workflow

Once an Object is published, you can use it in a Workflow with the **Datagraph Object** Data Node. The Node fetches external data for your Workflow.

1. Open your Workflow in the [Workflow editor](/product-guide/workflows/editor).
2. Add the **Datagraph Object** Data Node.
3. Select a published Object in the **Object** field.
4. Fill in each field under **Object parameters**. The Object's short description appears above its input.
5. Use the returned data in your [Content](/product-guide/contents/overview) or in a [Condition](/product-guide/workflows/logic-nodes/conditions).

See [Datagraph Object](/product-guide/workflows/data-nodes/datagraph) for the full Node walkthrough.

<Info>
  Only tech admins can configure this Node. Ask your administrator if it appears read-only. See [Permissions](/product-guide/account/permissions) for the Datagraph Schema and Datagraph permissions.
</Info>
