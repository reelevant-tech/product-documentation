title: 'Run an A/B Test with Split'
description: 'Compare Content options by assigning fixed audience percentages to Workflow Branches'
---

A Split Node (a Logic Node that assigns users to [Branches](/glossary)) lets you compare Content options using fixed audience percentages.

![Split Node configuration panel showing group distribution with percentage slider](/images/workflows/node-split.png)

## Before you begin

Choose the Content options you want to compare. Decide which result will identify the winner, such as clicks, conversions, or revenue.

Make sure every Branch will receive enough users for a useful comparison.

## Run your A/B test

<Steps>
  <Step title="Add a Split Node">
    1. Open your Workflow in the Workflow Editor.
    2. Choose **Create branches** where the comparison should begin.
    3. Select **Split**.
    4. Use **Add** to create at least two groups. Each group creates one Branch.
    5. Set each group's **Population share** with the slider. The shares must total 100%.

    Start with 50% for each group when you want an equal two-way comparison.
  </Step>

  <Step title="Build each Branch">
    Add the Nodes needed for each experience. Finish every Branch with an Output Node (a Node that returns the final response).

    Use a different [Visual Content Output Node](/product-guide/workflows/output-nodes/visual-content) for each Content option.

    To compare personalisation against no Reelevant Content, use an [Empty Output Node](/product-guide/workflows/output-nodes/empty) for the Non-Exposed Population.
  </Step>

  <Step title="Prepare your measurement">
    1. Right-click each Branch connection and select **Qualify branch**.
    2. Give every Branch a clear name.
    3. Apply a relevant category and a distinct tag value to each Branch.
    4. Confirm the measure you will compare in Analytics.

    For example, use the tag key `A/B test` with the values `A` and `B`.
  </Step>

  <Step title="Publish and measure">
    1. Click **Publish** to make the A/B test live.
    2. Use **Statistics mode** to check the traffic share for each Branch.
    3. Open [Analytics](/product-guide/analytics/overview).
    4. Compare your chosen measure by the tag used for the A/B test.

    <Tip>
      Avoid choosing a winner after only a few interactions. Let every Branch receive enough traffic for a meaningful comparison.
    </Tip>
  </Step>

  <Step title="Keep the winning Branch">
    1. Select the Branch that performed best for your chosen measure.
    2. Connect its Nodes directly to the Node before the Split Node.
    3. Delete the Split Node and the unused Branches.
    4. Check that the winning Branch still reaches its Output Node.
    5. Publish the updated Workflow.

    <Warning>
      Check every connection before publishing. You can restore an earlier setup from [Workflow Versions](/product-guide/workflows/versions).
    </Warning>
  </Step>
</Steps>

## How user assignment works

When a user triggers the Workflow, Reelevant assigns them according to your percentages. The same user will return to the same Branch.

This stable assignment gives each user a consistent Content experience during the A/B test.

## Split or Real-Time Testing?

| Your goal | Choose |
|---|---|
| Keep fixed audience shares and choose the winner yourself | **Split** |
| Let Reelevant adjust shares towards better-performing Content | [**Real-Time Testing**](/product-guide/workflows/logic-nodes/real-time-testing) |
