The Datagraph Object Data Node brings results from a published Object into your Workflow.

The drawer describes it as *Run a Datagraph object query and expose its results to the workflow.*

![Datagraph Object Data Node with a published Object selected and its parameter input configured](/images/workflows/node-datagraph-query.png)

## Overview

The **Datagraph Object** Data Node (a Node that fetches external data) makes a published [Datagraph](/product-guide/datahub/datagraph) Object's results available to later Nodes.

Use it when you need data from several Datasources at once. The Datagraph Object combines that data, so your Workflow can use the results.

<Warning>
  The Datagraph is in beta. Only tech admins can configure Datagraph object query nodes. Ask your administrator if the Node appears read-only.
</Warning>

## Adding the Node

1. Open your Workflow in the [Workflow editor](/product-guide/workflows/editor).
2. Hover over the **Data** button (database icon) in the bottom toolbar.
3. Click **Datagraph Object**.

![Data menu of the Workflow editor with the Datagraph Object option at the bottom of the list](/images/workflows/node-picker-data-datagraph.png)

## Configuring the Node

1. Choose an **Object** from **Select a published object**. Only published Objects appear.
2. Enter a value for each field under **Object parameters**.
3. Click **Confirm**.

The Node on the canvas then shows the name of the Object you selected.

![Datagraph Object Node on the Workflow canvas, showing the name of the selected Object](/images/workflows/node-datagraph-query-canvas.png)

### Object parameters

Each parameter displays its short description above the input. Enter a fixed value or choose a value from the Workflow.

![Datagraph Object parameter input with its type, short description, and available Workflow values](/images/workflows/node-datagraph-query-parameter.png)

<Tip>
  Use a Workflow value, such as a person identifier captured with a [URL Parameter](/product-guide/workflows/data-nodes/url-parameter) Node, to personalise results for each recipient.
</Tip>

### Result limit

By default, the **Result limit** control is hidden. It appears only when the **Datagraph Object: result limit** feature flag is enabled in the Workflows settings → **Features** tab.

Only tech admins can enable this flag. When available, the limit accepts between 1 and 200 rows.

Keep the limit close to what your [Content](/product-guide/contents/overview) displays. Requesting three products when you show three keeps your Workflow fast.

## Using the Data Downstream

The fields returned by the Object become available to the Nodes that follow, through the **Variable Picker**. You can use them in your Content, or in a [Condition](/product-guide/workflows/logic-nodes/conditions) to change what each person sees.

<Info>
  The empty selector says *No published object is available yet.* Ask your data team to publish an Object in **DataHub → Datagraph → Objects**.
</Info>

## Best Practices

- Preview the Object in the DataHub first, so you know which fields it returns. **Open object in Datahub** opens it from the Object field.
- Give every parameter a value. An Object that misses a mandatory parameter returns nothing.
- Re-open the Node after your data team publishes a new version of the Object, to check that the parameters still match.

## Using Object Families in Contents

An Object family lets a Workflow provide any published Object that belongs to the family. Select the family as a source when [binding Content data](/product-guide/contents/data-binding).
