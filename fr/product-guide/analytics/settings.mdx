## Vue d'ensemble

La page Paramètres Analytics permet de configurer l'attribution, l'exposition à la personnalisation, les tags personnalisés et les catégories de branche de votre entreprise. Utilisez les tags et les catégories pour qualifier les branches et segmenter Analytics.

Accédez-y depuis le lien **Settings** dans la navigation latérale d'Analytics.

## Attribution

L'attribution montre la part de chiffre d'affaires générée avec l'aide de vos [Workflows](/fr/product-guide/workflows/overview) Reelevant. Choisissez les paramètres adaptés à vos achats et à vos objectifs de reporting.

![Configuration de l'attribution sur l'onglet Général : jeu de données, source d'attribution, modèle, méthode et canaux de conversion avec fenêtres rétrospectives](/images/analytics/attribution-settings-reelevant.png)

### Jeu de données et source d'attribution

Choisissez d'abord le **Jeu de données**, puis la **Source d'attribution**. Les paramètres UTM sont disponibles uniquement avec **Suivi web**, car les enregistrements d'achats clients ne contiennent pas d'URL.

| Paramètre | Options et comportement | Exemple |
|---|---|---|
| **Jeu de données** | **Suivi web** enregistre les achats suivis par Reelevant. **Achats clients** utilise les achats transmis par votre entreprise. | Une marque uniquement web choisit Suivi web. Un détaillant dont le CRM ou l'ERP rassemble les ventes en magasin et sur le web choisit Achats clients. |
| **Source d'attribution** | **Interactions Reelevant** crédite les interactions avec le Content Reelevant. **Paramètres UTM** mesure les visites taggées UTM et n'est disponible qu'avec Suivi web. | Choisissez Interactions Reelevant pour isoler la contribution de Reelevant, ou Paramètres UTM pour comparer la recherche payante, les e-mails et les affiliés. |

### Modèle d'attribution

Le modèle répartit le crédit entre les interactions éligibles avant un achat.

| Modèle | Répartition du crédit | Exemple |
|---|---|---|
| **Dernier contact** (par défaut) | La dernière interaction éligible reçoit tout le crédit. | Choisissez-le pour comparer vos résultats au reporting last-click classique. |
| **Linéaire** | Chaque interaction éligible reçoit une part égale. | Choisissez-le quand les interactions par e-mail, sur le site et dans l'application comptent toutes. |
| **Décroissance temporelle** | Les interactions proches de l'achat reçoivent plus de crédit, sans supprimer les premières contributions. | Choisissez-le quand une marque d'abonnement veut favoriser les interactions récentes tout en gardant les premières assistances. |
| **Incrémental** | Le crédit suit l'Uplift mesuré pour chaque Channel, type d'entrée du Workflow, par rapport à une base modélisée sans personnalisation. Les parts sont recalculées pour totaliser l'achat. Ce n'est pas un groupe témoin randomisé. | Comparez l'Uplift mesuré des Channels e-mail et onsite, avec la mesure du dashboard Uplift. |

### Méthode d'attribution

| Méthode | Fonctionnement | Exemple |
|---|---|---|
| **Par défaut** | Crédite toute interaction éligible du client. | Choisissez-la lorsqu'une interaction pertinente peut avoir influencé l'achat. |
| **Même identifiant de référence** | Crédite une interaction uniquement si l'identifiant de référence du produit acheté correspond à un produit affiché dans le Content. Les identifiants produits proviennent des métadonnées Datasource de l'Output Node. | Choisissez-la pour un Workflow de recommandation de produits lorsque seul l'achat d'un produit recommandé doit être crédité. |

### Précision de l'heure d'achat

Ce paramètre apparaît uniquement avec **Achats clients**.

| Option | Fonctionnement | Exemple |
|---|---|---|
| **Date et heure** (par défaut) | L'interaction doit précéder l'horodatage de l'achat. Suivi web utilise toujours cette précision. | Gardez cette option lorsque les achats ont une heure réelle ; elle évite de créditer un clic d'après-midi après un achat matinal. |
| **Date uniquement** | Traite l'achat comme une journée. Les interactions jusqu'à la fin de cette journée peuvent être créditées ; la fenêtre commence toujours à minuit. | Choisissez-la pour les tickets de caisse exportés sans heure, dont chaque achat est à minuit. |

### Canaux de conversion

Les canaux de conversion sont disponibles avec **Interactions Reelevant**. Chaque canal comprend une **Clé du canal** et des **Interactions**, avec un type et une **Fenêtre d'attribution (heures)**.

**Suivi web** utilise un canal `web` fixe. Avec **Achats clients**, la clé du canal correspond à la source de transaction de l'achat. Un achat sans clé correspondante est exclu, sauf si **Toute autre source (*)** est configuré ; il prend alors en charge toutes les sources sans canal dédié.

| Paramètre | Options et comportement | Exemple |
|---|---|---|
| **Clé du canal** | Correspond à la source de transaction. **Toute autre source (*)** récupère les sources sans canal correspondant. | Configurez `store` et `web` séparément si leurs parcours diffèrent. Ajoutez `*` pour ne pas exclure une nouvelle source comme une marketplace. |
| **Interactions** | Ajoutez **Clic** et/ou **Affichage**. Par défaut, Clic vaut 720 heures (30 jours) et Affichage 168 heures (7 jours). | Une marque qui utilise beaucoup l'e-mail peut ajouter Affichage pour compter les ouvertures ; les ouvertures privées Apple Mail comptent aussi, ce qui est généreux. |
| **Fenêtre d'attribution (heures)** | Définit la durée pendant laquelle chaque type d'interaction peut recevoir du crédit avant l'achat. | Utilisez Clic et Affichage avec une fenêtre de 48 heures pour les achats en magasin, où les clics sont rares. Pour le web, utilisez Clic sur 720 heures. |

### Configuration UTM

Avec **Paramètres UTM**, choisissez la granularité UTM et la fenêtre rétrospective.

| Paramètre | Options et comportement | Exemple |
|---|---|---|
| **Granularité UTM** | Choisissez Source, Medium, Campaign, Term et/ou Content. Source et Medium sont sélectionnés par défaut. | Gardez Source et Medium pour une vue par canal ; ajoutez Campaign pour comparer les campagnes. |
| **Fenêtre d'attribution (heures)** | Valeur par défaut : 720 heures. | Gardez 720 heures lorsque les campagnes peuvent influencer un achat pendant 30 jours. |

### Tunnel de conversion

Le tunnel facultatif contient des entrées ordonnées **Step name** et **Events**. La dernière étape est la conversion.

| Paramètre | Fonctionnement | Exemple |
|---|---|---|
| **Tunnel de conversion** | Ajoutez dans l'ordre les événements qui marquent chaque étape. | Une marque de génération de leads peut utiliser `signup_start`, puis `signup_complete`. |

### Configurer l'attribution

1. Rendez-vous dans **Analytics > Settings**.
2. Ouvrez l'onglet **Général** et choisissez un **Jeu de données** et une **Source d'attribution**.
3. Choisissez le **Modèle d'attribution** et la **Méthode d'attribution**.
4. Configurez les canaux de conversion, les paramètres UTM ou le tunnel lorsqu'ils sont disponibles.
5. Avec Achats clients, choisissez la **Précision de l'heure d'achat**.
6. Cliquez sur **Enregistrer les modifications**.

<Info>
  Modifier l'attribution affecte le [tableau de bord Conversions](/fr/product-guide/analytics/dashboards/conversions) et [Data Exploration](/fr/product-guide/analytics/data-exploration). Une fenêtre plus longue peut créditer davantage d'interactions.
</Info>

## Cycle de vie client

Les paramètres du cycle de vie client définissent les seuils d'achat et les périodes utilisés pour classer les clients. Laissez un champ vide pour conserver sa valeur par défaut.

Les stades comprennent `prospect`, `one-time`, `repeater`, `loyal`, `at-risk` et `churned`.

| Paramètre | Par défaut | Rôle | Exemple |
|---|---:|---|---|
| **Fenêtre d'activité (jours)** | 180 | Période utilisée pour identifier les clients actifs. | Un détaillant de meubles avec des achats annuels peut choisir 365 jours ; une marque de produits de beauté réapprovisionnés, 90 jours. |
| **Fenêtre d'attrition (jours)** | 365 | Sans achat après cette période, le client est churned ; entre les fenêtres d'activité et d'attrition, il est at-risk. | Un détaillant de meubles peut choisir 730 jours ; une marque de réapprovisionnement, 180 jours. |
| **Achats pour être répété** | 2 | Nombre d'achats requis pour atteindre le stade repeater. | Gardez 2 si un second achat de courses ou de produits de beauté indique déjà une répétition. |
| **Achats pour être fidèle** | 5 | Achats requis pour qu'un client actif soit considéré comme loyal. | Une marque de beauté peut augmenter ce seuil pour réserver le stade aux acheteurs réguliers. |
| **Fenêtre d'historique (jours)** | 730 | Période pendant laquelle Analytics lit les achats. | Utilisez 180 jours si un jeu de données réingéré récemment ne contient que six mois d'historique. |
| **Fenêtre d'exposition (jours)** | 90 | Période pendant laquelle un client compte comme exposé à Reelevant. | Un cycle d'achat long peut justifier 180 jours pour inclure les interactions personnalisées antérieures. |

## Reporting

Le **TCO (coût total de possession)** correspond au coût mensuel de la plateforme Reelevant. Analytics le répartit sur la période sélectionnée pour les mesures de coût et de ROI.

| Paramètre | Rôle | Exemple |
|---|---|---|
| **Coût total de possession (TCO)** | Coût mensuel utilisé par les mesures de coût et de ROI. À 0 ou vide, les rapports ne calculent pas le ROI. | Saisissez le coût mensuel de Reelevant pour comparer le chiffre d'affaires du rapport au coût réel de la plateforme. |

Utilisez l'onglet **Rapports automatiques** pour configurer des rapports périodiques. Consultez le [guide des rapports](/fr/product-guide/analytics/reports) et le [guide avancé](/fr/advanced-guide/analytics/reports).

## Exposition à la personnalisation

Ces deux seuils décident quels clients comptent comme personnalisés dans le dashboard [Impact client](/fr/advanced-guide/analytics/customer-impact). Ce dashboard et [Adoption](/fr/advanced-guide/analytics/adoption) sont tous deux en bêta et activés sur demande : vous ne les voyez peut-être pas encore.

![Paramètres d'exposition à la personnalisation avec les champs affichages personnalisés minimum et part personnalisée minimum](/images/analytics/analytics-settings-personalisation-exposure.png)

| Champ | Par défaut | Rôle | Exemple |
|---|---:|---|---|
| **Affichages personnalisés minimum** | 2 | Combien de Contents personnalisés un client doit avoir vus. | Un détaillant à fort volume peut exiger plusieurs affichages avant de compter un client comme personnalisé. |
| **Part personnalisée minimum (%)** | 50 | Quelle part de ce qu'il a vu doit être personnalisée. | Relevez-la si votre entreprise personnalise la plupart de ses Contents et veut un groupe plus régulièrement exposé. |

Les clients au-dessus de zéro mais sous ces seuils ne comptent ni comme personnalisés ni comme non personnalisés. Ils restent hors de la comparaison.

1. Rendez-vous dans **Analytics > Settings**.
2. Faites défiler jusqu'à **Exposition à la personnalisation** sur l'onglet **General**.
3. Définissez les deux seuils, ou laissez-les vides pour conserver les valeurs par défaut.
4. Cliquez sur **Enregistrer les modifications**.

<Tip>
  Relevez **Part personnalisée minimum (%)** lorsque votre entreprise personnalise la plupart de ses Contents. Abaissez-la lorsque seuls quelques Contents le sont.
</Tip>

## Fiabilité de la comparaison

Ce seuil décide quand le dashboard [Impact client](/fr/advanced-guide/analytics/customer-impact) affiche un chiffre d'Uplift, et quand il le laisse vide.

| Champ | Par défaut | Rôle | Exemple |
|---|---:|---|---|
| **Minimum de clients par cohorte** | 100 | Combien de clients chaque côté de la comparaison doit compter. | Une grande entreprise peut l'augmenter pour réduire les Uplifts instables. Une petite entreprise B2B peut l'abaisser pour garder de petites cohortes, avec moins de fiabilité. |

Les deux côtés ont besoin de ce nombre de clients : les clients personnalisés et les clients non personnalisés comparables. En dessous, le dashboard affiche les effectifs mais aucun chiffre.

Une moyenne calculée sur une poignée de clients bouge au rythme d'un seul panier. Un chiffre vide signifie donc « nous ne pouvons pas répondre », et non « aucun effet ».

1. Rendez-vous dans **Analytics > Settings**.
2. Faites défiler jusqu'à **Fiabilité de la comparaison** sur l'onglet **General**.
3. Définissez le seuil, ou laissez-le vide pour conserver la valeur par défaut.
4. Cliquez sur **Enregistrer les modifications**.

<Info>
  Impact client exige aussi une période d'au moins un mois. Sur une période plus courte, être touché par Reelevant et être actif sont presque la même chose. C'est pourquoi le dashboard s'ouvre sur les trois derniers mois.
</Info>

## Tags

Les tags donnent à chaque branche des libellés contrôlés que votre équipe utilise de manière cohérente dans les Workflows et Analytics.

Chaque tag contient une **clé de tag** (le libellé à organiser) et une liste de **valeurs**. Par exemple, `Objectif de campagne` peut contenir `Acquisition` et `Fidélisation`.

Seuls les tags personnalisés apparaissent dans cet onglet. Les tags gérés par Reelevant ne peuvent pas être modifiés.

### Comprendre la cardinalité

La cardinalité contrôle le nombre de valeurs d'une clé de tag attribuables à une même branche. Elle ne limite pas le nombre de valeurs créées.

![Panneau de création d'une clé de tag présentant les cardinalités Unique et Multiple](/images/analytics/tag-cardinality.png)

| Cardinalité | Comportement dans un Workflow | Exemple |
|---|---|---|
| **Unique** | Chaque branche finale retient une valeur de cette clé de tag. | `Objectif de campagne : Fidélisation` ne peut pas être associé à `Objectif de campagne : Acquisition` sur la même branche. |
| **Multiple** | Chaque branche finale conserve toutes les valeurs attribuées. | `Contexte d'audience : Anniversaire` et `Contexte d'audience : Fidélité` peuvent décrire la même branche. |

**La plus en aval** désigne la qualification la plus proche de l'[Output Node](/fr/glossary).

Imaginez un Workflow qui attribue `Objectif de campagne : Acquisition` avant un second Logic Node.

Une qualification ultérieure sur la même branche finale attribue `Objectif de campagne : Fidélisation`. Analytics utilise `Fidélisation`, car cette valeur est plus proche de l'Output Node.

Avec la cardinalité **Multiple**, les deux valeurs restent attribuées à la branche finale.

<Tip>
  Choisissez **Unique** lorsqu'une valeur en aval doit remplacer les précédentes. Choisissez **Multiple** pour conserver toutes les valeurs rencontrées.
</Tip>

### Créer une clé de tag

1. Rendez-vous dans **Analytics > Settings**.
2. Sélectionnez **Tags**.
3. Cliquez sur **Ajouter un tag**.
4. Saisissez un **Nom** unique.
5. Ajoutez une **Description** facultative pour guider vos coéquipiers.
6. Choisissez **Unique** ou **Multiple** sous **Cardinalité**.
7. Cliquez sur **Créer la clé de tag**.

Les noms des clés de tag doivent être uniques. La plateforme ignore la casse et les espaces placés au début ou à la fin.

### Ajouter des valeurs

1. Trouvez la clé de tag.
2. Cliquez sur l'icône plus à côté de **Valeurs**.
3. Saisissez un nom de valeur unique et une description facultative.
4. Cliquez sur **Ajouter une valeur**.

Les noms des valeurs doivent être uniques dans leur clé. Développez **Valeurs** pour consulter tous les choix disponibles.

La plateforme ignore aussi la casse et les espaces placés au début ou à la fin des valeurs.

### Modifier ou supprimer des tags

Utilisez l'icône crayon pour modifier une clé de tag, sa description ou sa cardinalité.

Développez **Valeurs**, puis utilisez les icônes de chaque valeur pour la modifier ou la supprimer.

<Warning>
  Supprimer une clé de tag supprime également toutes ses valeurs. Les clés et valeurs supprimées ne peuvent pas être restaurées.
</Warning>

### Utiliser les tags dans les Workflows et Analytics

Les tags créés deviennent disponibles lorsque vous [qualifiez une branche](/fr/product-guide/workflows/branches). Les utilisateurs sélectionnent les valeurs contrôlées sans en créer de nouvelles.

Dans Analytics, utilisez les clés et valeurs pour filtrer les résultats ou comparer les performances de vos qualifications.

## Catégories de branche

![Onglet des paramètres de catégories de branche affichant l'arbre de catégories](/images/workflows/branch-categories-settings-v2.png)

Les catégories de branche forment un arbre hiérarchique utilisé pour **qualifier les branches** dans tous vos Workflows. Elles donnent à votre équipe un vocabulaire partagé et alimentent le filtrage Analytics par catégorie.

Ouvrez l'onglet **Catégories de branches** dans les Paramètres Analytics pour les gérer aux côtés de vos tags.

### Visualiser l'arbre de catégories

L'onglet affiche votre arbre de catégories sous forme de hiérarchie interactive et dépliable. Chaque catégorie affiche :
- **Nom** — Le libellé de la catégorie.
- **Niveau** — Sa profondeur dans l'arbre.
- **Enfants** — Les sous-catégories imbriquées en dessous.

### Créer une catégorie

<Steps>
  <Step title="Ouvrir le formulaire">
    Cliquez sur le bouton **Add** pour ouvrir le panneau de création de catégorie.
  </Step>
  <Step title="Remplir les détails">
    - **Nom** — Un nom descriptif pour la catégorie (ex. : « Product Recommendation »).
    - **Parent** — Sélectionnez optionnellement une catégorie parente pour imbriquer celle-ci en dessous.
  </Step>
  <Step title="Enregistrer">
    Cliquez sur **Save** pour ajouter la catégorie à l'arbre.
  </Step>
</Steps>

### Modifier une catégorie

Cliquez sur une catégorie existante dans l'arbre pour ouvrir le panneau de modification. Vous pouvez mettre à jour le nom ou la déplacer sous un autre parent.

### Supprimer une catégorie

<Warning>
  La suppression d'une catégorie la retire de tous les Workflows où elle est utilisée. Les branches qui référençaient la catégorie supprimée perdront leur qualification.
</Warning>

1. Sélectionnez la catégorie dans l'arbre.
2. Cliquez sur le bouton **Delete**.
3. Confirmez la suppression dans la modale de confirmation.

### Bonnes pratiques

- **Concevez pour l'Analytics** — Structurez votre arbre autour des dimensions à analyser (ex. : type de stratégie, catégorie de contenu, segment d'audience).
- **Restez suffisamment plat** — Un arbre trop profond est plus difficile à parcourir. Visez 2-3 niveaux maximum.
- **Nommez clairement** — Utilisez des noms descriptifs compréhensibles par toute l'équipe sans contexte.
