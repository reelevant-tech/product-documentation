Le Datagraph fait partie du [DataHub](/fr/product-guide/datahub/overview). Vous pouvez décrire les liens entre vos Datasources et réutiliser ces données fiables dans vos Workflows.

<Warning>
  Le Datagraph est en bêta. Ses pages et ses options peuvent encore évoluer. Échangez avec votre Technical Account Manager avant de vous appuyer dessus dans un Workflow en production.
</Warning>

## Pourquoi utiliser le Datagraph ?

Chaque Datasource contient un seul ensemble de données : produits, magasins, achats ou clients. Seule, une Datasource ne peut pas répondre à une question qui croise deux ensembles de données.

Le Datagraph relie vos Datasources. Votre équipe data peut créer des Objets réutilisables, par exemple « les cinq produits les plus achetés par cette personne ». N'importe quel Workflow peut les utiliser.

<Tip>
  Vous n'avez pas à construire le Datagraph vous-même. Il est généralement mis en place une fois par votre équipe data ou votre Technical Account Manager Reelevant, puis réutilisé par tout le monde.
</Tip>

## Où le trouver

Ouvrez **DataHub** dans la barre latérale, puis choisissez **Datagraph**. Utilisez ces pages pour explorer le modèle et ses Objets réutilisables :

| Page | À quoi elle sert |
|------|------------------|
| **Schema** | Modifiez le modèle dans **Visual** ou explorez-le dans **Diagram**, **Relations** et **Datasources**. |
| **Objets** | Des résultats réutilisables construits sur le modèle, prêts à être utilisés dans les Workflows. |
| **Familles d'objets** | Des Objets avec les mêmes champs de sortie, pour qu'un Workflow puisse utiliser différents membres. |

Dans **Objets**, choisissez **Créer un objet** pour ajouter un Objet. La liste affiche **Aucun objet pour le moment** avant sa création.

Dans **Familles d'objets**, choisissez **Créer une famille** pour définir les champs de sortie communs.

Dans **Schema**, utilisez **Visual** pour modifier les tables. Choisissez **Diagram**, **Relations** ou **Datasources** pour explorer le modèle.

![Vue Visual de la page Schema avec un modèle immobilier, cinq tables SeLoger et les colonnes de la table utilisateurs sélectionnée](/images/datahub/datagraph-seloger-schema.png)

L'onglet **Relations** présente les liens entre tables et les champs utilisés.

![Onglet Relations de la page Schema du Datagraph, montrant les liens des recommandations vers les utilisateurs et les annonces](/images/datahub/datagraph-seloger-schema-relations.png)

## Explorer le modèle

La page Schema propose plusieurs vues pour explorer le modèle et vérifier ses liens.

1. Ouvrez **DataHub → Datagraph → Schema**.
2. Choisissez l'onglet **Diagram** pour voir les Datasources sous forme de blocs reliés.
3. Faites glisser le diagramme pour vous déplacer, et utilisez les boutons de zoom pour vous rapprocher.
4. Ouvrez l'onglet **Relations** pour examiner chaque lien un par un.
5. Ouvrez l'onglet **Datasources** pour lister les Datasources utilisées dans le modèle, avec leurs champs.

![Onglet Diagram de la page Schema du Datagraph, avec cinq Datasources immobilières liées sous forme de blocs reliés](/images/datahub/datagraph-seloger-explorer.png)

<Info>
  Les onglets **Diagram**, **Relations** et **Datasources** affichent le Draft s'il existe. Sinon, ils affichent la version Published.
</Info>

Sur l'onglet **Relations**, chaque lien affiche un pourcentage **Join match**. Il indique le recoupement des valeurs des deux côtés dans vos données.

![Onglet Relations de la page Schema du Datagraph, listant cinq liens avec leur pourcentage de join match](/images/datahub/datagraph-seloger-relations.png)

| Filtre | Ce qu'il affiche |
|--------|------------------|
| **All** | Tous les liens du modèle. |
| **Good** | Les liens dont les valeurs se recoupent bien. |
| **Weak** | Les liens dont le recoupement est faible — à examiner avec votre équipe data. |
| **Invalid** | Les liens qui n'ont pas pu être vérifiés du tout. |

<Warning>
  Un lien faible ou invalide signifie généralement que les deux Datasources ne partagent pas les mêmes identifiants. Une personnalisation construite sur ce lien peut ne rien retourner : signalez-le à votre équipe data avant de l'utiliser dans un Workflow.
</Warning>

## Versions Draft et Published

La page **Schema** affiche un badge de statut **Draft** ou **Published**. Chaque Objet possède également sa propre version.

| Statut | Signification |
|--------|---------------|
| **Draft** | Travail en cours. Visible uniquement dans les pages du Datagraph. |
| **Published** (ou **Live**) | La version réellement utilisée par les Workflows. |
| **Inactive** | Une version publiée précédemment, conservée pour l'historique. |

Rien de ce que vous voyez dans un Draft n'affecte votre personnalisation en production avant publication.

![Liste des Objets Datagraph avec les colonnes Nom, Statut et Dernière mise à jour](/images/datahub/datagraph-seloger-entities.png)

## Questions auxquelles un Objet peut répondre

Un Objet répond à une question sur une personne, un produit ou une zone. Votre équipe data le prépare une fois, et tous les Workflows peuvent le réutiliser.

Voici des exemples typiques pour un compte d'annonces immobilières :

| Objet | La question à laquelle il répond |
|--------|------------------------------------|
| **Listings matching a user search** | Quelles annonces se trouvent dans la zone recherchée par cette personne, dans son budget ? |
| **Listings with a recent price drop** | Quelles annonces d'une zone viennent de baisser, la plus forte baisse d'abord ? |
| **Market prices in the user area** | Quel est le prix médian au mètre carré et la tendance dans la zone recherchée ? |
| **Recommended listings for a user** | Quelles annonces nos données de recommandation suggèrent-elles pour cette personne ? |
| **Editorial content for an area** | Quels guides et articles de marché sont publiés pour cette zone ? |

Les mêmes principes fonctionnent pour d'autres secteurs. Un compte retail peut demander les derniers articles achetés, le stock restant dans le magasin préféré, ou les meilleures ventes de la catégorie préférée.

<Tip>
  Décrivez la question dont vous avez besoin en langage courant, avec les données attendues. Votre équipe data la transforme en Objet, puis vous le choisissez dans votre Workflow.
</Tip>

L'éditeur d'Objet propose les champs **Nom de l'objet** et **Objet édité**, ainsi que les panneaux **INPUT / OUTPUT** et **VERSIONS**. L'aperçu aide à vérifier les valeurs retournées.

![Éditeur d'Objet Datagraph avec les champs Nom de l'objet et Objet édité, les panneaux latéraux INPUT / OUTPUT et VERSIONS, et le panneau PREVIEW & RESULTS replié](/images/datahub/datagraph-seloger-entity-editor.png)

Le panneau **INPUT / OUTPUT** liste les paramètres et les champs retournés. Les types affichés sont **Texte**, **Nombre** ou **URL d'image**.

![Panneau INPUT / OUTPUT avec le paramètre user_id et les champs retournés de types Texte, Nombre et URL d'image](/images/datahub/datagraph-seloger-entity-input-output.png)

## Utiliser un Objet dans un Workflow

Une fois publié, vous pouvez utiliser un Objet dans votre Workflow avec le Data Node **Objet Datagraph**, une étape qui récupère des données externes.

1. Ouvrez votre Workflow dans l'[éditeur de Workflow](/fr/product-guide/workflows/editor).
2. Ajoutez le Data Node **Objet Datagraph**.
3. Sélectionnez un Objet publié dans le champ **Objet**.
4. Renseignez chaque champ sous **Paramètres de l'objet**. La courte description de chaque paramètre apparaît au-dessus de son champ.
5. Utilisez les données retournées dans votre [Content](/fr/product-guide/contents/overview) ou dans une [Condition](/fr/product-guide/workflows/logic-nodes/conditions).

Voir [Objet Datagraph](/fr/product-guide/workflows/data-nodes/datagraph) pour la description complète du Node.

<Info>
  Seuls les administrateurs techniques peuvent configurer les nœuds d'interrogation d'objet Datagraph. Demandez à votre administrateur si le Node apparaît en lecture seule. Voir [Permissions](/fr/product-guide/account/permissions) pour les permissions Datagraph Schema et Datagraph.
</Info>
