## Vue d'ensemble

Le tag de tracking est un petit script d'amorçage qui charge le tracker Reelevant et expose `window.reel`. Deux lignes suffisent pour envoyer un événement :

```html
<script src="https://scripts-repo.reelevant.com/tag-rlvt?company={companyId}&datasource={datasourceId}"></script>
<script>
  window.reel.identify('user@example.com')
  window.reel.event('product_page', { ids: ['SKU-12345'], locale: 'EN-GB' })
</script>
```

Dans cet exemple, l'amorçage est chargé de manière synchrone : les appels sont mis en attente pendant le chargement du tracker et de sa configuration. Avec un amorçage `async`, attendez son chargement avant d'appeler `window.reel`.

Le snippet exact, avec vos `companyId` et `datasourceId` déjà substitués, est affiché par l'étape **Configure Reelevant Script** de l'assistant de la Datasource de tracking.

## Installation

<CodeGroup>

```html Tag
<!-- Dans <head>, ou avant </body> -->
<script src="https://scripts-repo.reelevant.com/tag-rlvt?company={companyId}&datasource={datasourceId}" async></script>
```

```typescript SPA
// Chargez le tag une fois, puis suivez vous-même les changements de route.
// Les types ne sont pas publiés — déclarez la surface que vous utilisez.
declare global {
  interface Window {
    reel: {
      queue: [string, Record<string, unknown>?][]
      event(name: string, data?: Record<string, unknown>): void
      identify(clientId: string): void
      loadZones(): Promise<void>
      getClientId(): string | undefined
    }
  }
}

export const trackProductView = (productId: string, locale: string): void => {
  if (typeof window.reel === 'undefined') return
  window.reel.event('product_page', { ids: [productId], locale })
}
```

</CodeGroup>

### Tag mis à jour automatiquement (par défaut)

L'URL `/tag-rlvt?company=&datasource=` reste compatible. Son amorçage charge la dernière version du tracker depuis la même origine. Conservez cette option pour recevoir automatiquement les mises à jour ; n'attachez pas d'empreinte SRI fixe à cet amorçage évolutif.

Le tracker récupère `/config?company=&datasource=` depuis l'origine de son script pour obtenir les URL de collecte et les intégrations de Workflow. Cette configuration évolue indépendamment du fichier JavaScript statique.

Charger le tag deux fois n'a aucun effet : l'amorçage s'arrête immédiatement si `window.reel` existe déjà.

### Version figée avec Subresource Integrity (SRI)

Récupérez le manifeste lors de la préparation du déploiement, et non à chaque visite :

```bash
curl --fail --silent --show-error https://scripts-repo.reelevant.com/rlvt.json
```

Exemple de réponse pour la version `1.1.0` :

```json
{
  "version": "1.1.0",
  "url": "https://scripts-repo.reelevant.com/rlvt-1.1.0.js",
  "integrity": "sha384-Z8mA0aO/5Puep/gsARGJdIeW3awJhFGk7S9nFN3JJVNBFK1+8TUg+oUH+Lo8st7N"
}
```

Copiez ensemble les valeurs `url` et `integrity` retournées. Remplacez les identifiants d'exemple par ceux de votre entreprise et de votre Datasource :

```html
<script>
  window.reel = { companyId: '507f1f77bcf86cd799439011', datasourceId: '507f191e810c19729de860ea' }
</script>
<script src="https://scripts-repo.reelevant.com/rlvt-1.1.0.js" integrity="sha384-Z8mA0aO/5Puep/gsARGJdIeW3awJhFGk7S9nFN3JJVNBFK1+8TUg+oUH+Lo8st7N" crossorigin="anonymous" async></script>
```

Les versions publiées sont immuables. Pour une mise à niveau volontaire, remplacez les deux attributs depuis un nouveau manifeste. Une version inconnue renvoie `404` ; une empreinte incorrecte bloque l'exécution dans le navigateur.

Si la récupération du manifeste échoue, conservez votre version figée plutôt que de déployer un snippet incomplet.

| Paramètre | Type | Obligatoire | Défaut | Description |
|-----------|------|-------------|--------|-------------|
| `window.reel.companyId` | `string` | Oui | Aucun | Identifiant de l'entreprise. |
| `window.reel.datasourceId` | `string` | Oui | Aucun | Identifiant de la Datasource de tracking. |
| `window.reel.customCode` | `boolean` | Non | `false` | Activation explicite du code personnalisé. |
| `src` | URL | Oui | Aucun | Champ `url` immuable du manifeste. |
| `integrity` | `string` | Oui | Aucun | Empreinte SHA-384 du manifeste. |
| `crossorigin` | `string` | Oui, pour SRI | Aucun | Valeur `anonymous`. |
| `async` | Attribut booléen | Non | Absent | Chargement sans bloquer l'analyse HTML. |

Ce snippet minimal n'installe pas de méthodes temporaires avant le chargement du fichier. Attendez l'événement `load` du script externe avant d'appeler `event()` ou `identify()`.

### Intégrations de code personnalisé

Les installations figées exécutent ce code uniquement si les deux conditions suivantes sont réunies :

- Reelevant a activé `workflow_integration_custom_code` pour votre entreprise.
- Vous définissez explicitement `customCode: true` dans `window.reel` avant de charger le tracker.

Ajoutez par exemple `customCode: true` à côté de `companyId` et `datasourceId` dans l'initialisation ci-dessus. Le code est désactivé sinon. L'amorçage historique `/tag-rlvt` active déjà cette option : les installations existantes continuent donc à l'exécuter lorsque Reelevant l'autorise pour l'entreprise.

Sans activation pour l'entreprise, l'enregistrement d'un code non vide nouveau ou modifié renvoie `403`. La suppression reste autorisée. Contactez Reelevant pour demander l'activation ; modifier l'option du navigateur ne contourne pas cette restriction.

### Content Security Policy

Ajoutez ces sources à la CSP existante de votre site, en conservant celles nécessaires à votre application :

```text
script-src 'self' https://scripts-repo.reelevant.com;
connect-src 'self' https://scripts-repo.reelevant.com https://reelevant.run https://collector.reelevant.com;
```

Autorisez l'initialisation inline de `window.reel` avec une empreinte CSP ou un nonce renouvelé à chaque réponse, présent sur le `<script>` et dans `script-src`. N'autorisez pas tous les scripts inline uniquement pour cette initialisation.

Ajoutez `'unsafe-eval'` à `script-src` uniquement si vous activez les intégrations de code personnalisé, qui utilisent `eval`. SRI fige le fichier, pas la configuration dynamique, le code personnalisé ni le [Content](/fr/glossary) rendu.

Le Runner de production est `https://reelevant.run` et la collecte utilise `https://collector.reelevant.com`. Si votre entreprise utilise un domaine Runner personnalisé, autorisez-le aussi dans `connect-src`.

Le HTML web rendu peut contenir des scripts inline ou des gestionnaires d'événements nécessitant une revue CSP distincte, indépendamment du code personnalisé des intégrations.

## API `window.reel`

| Méthode | Signature | Description |
|---------|-----------|-------------|
| `event` | `(name: string, data?: Record<string, unknown>) => void` | Envoie un événement. `data` doit être un objet simple — tableaux et primitives sont rejetés avec une erreur console. |
| `identify` | `(clientId: string) => void` | Stocke l'identité connue dans `rlvt_clientId` et envoie un événement `identify`. |
| `getClientId` | `() => string \| undefined` | Identité connue actuelle (`rlvt_clientId`, ou `rlvt_id` si le visiteur arrive d'un lien Reelevant). |
| `loadZones` | `() => Promise<void>` | Ré-attache les [intégrations on-site](/fr/developer-docs/web-integration/client-side-script/overview). À appeler après une navigation côté client. |

`window.reel.event` et `window.reel.identify` sont remplacées par les implémentations réelles au chargement du tracker ; avant cela, elles poussent dans `window.reel.queue`.

Des événements et des identités sont aussi lus dans la page sans aucun appel de votre part :

| Source | Effet |
|--------|-------|
| Paramètre `?rlvt-u=`, `?rlvt_u=`, `?clientUid=`, ou fragment `#rlvt-u=` | Stocké dans `rlvt_clientId` |
| Variable globale `window.reelevant_user` | Stockée dans `rlvt_clientId` |
| Paramètre `?rlvt_id=` | Stocké dans `rlvt_id` — l'identité destinataire d'un lien Reelevant, utilisée à la place de `clientId` sur les événements suivants |
| Clés contenant `locale`, `language` ou `country` dans le dataLayer | Ajoutées en majuscules à chaque payload sous `locale` / `country` |

<Note>
  `page_view` est écarté par le tracker web — l'URL de la page est déjà portée par le champ `url` de tous les autres événements. Utilisez un nom d'événement personnalisé si vous avez besoin d'un événement explicite au niveau page.
</Note>

## Google Tag Manager

Le [template GTM côté client](https://github.com/reelevant-tech/gtm-template-website-tracker-client) encapsule le même tag. Configurez un tag par type d'événement :

| Champ du template | Valeur |
|-------------------|--------|
| **Company ID** / **Datasource ID** | Identifiants issus de l'assistant de la Datasource |
| **Event** | `init`, `identify`, `product_page`, `product_hover`, `category_view`, `brand_view`, `add_cart`, `purchase`, `purchase_references` ou `custom` |
| **Global labels** | Paires clé/valeur fusionnées dans tous les événements envoyés depuis le conteneur |
| **Labels** | Paires clé/valeur fusionnées dans cet événement uniquement |

Déclenchez d'abord l'événement `init` : il injecte le tracker et préserve les événements déjà en file. Les autres tags poussent dans `window.reel.queue`, l'ordre de déclenchement n'a donc pas d'importance.

`purchase_references` est la variante par référence de `purchase` : utilisez-la lorsque votre dataLayer expose des références catalogue au lieu d'identifiants produit, afin que l'[attribution sur la même référence](/fr/product-guide/analytics/attribution) puisse relier l'achat au Content affiché.

## Cookies d'identité

| Cookie | Durée de vie | Défini par |
|--------|--------------|------------|
| `rlvt_tmpId` | 365 jours | Le tracker, au premier chargement — un cuid, toujours envoyé comme `tmpId` |
| `rlvt_clientId` | 180 jours | `identify()`, un paramètre d'URL, ou `window.reelevant_user` |
| `rlvt_id` | 30 jours | Le paramètre d'URL `rlvt_id` d'un lien Reelevant |

Les cookies sont écrits sur le domaine enregistrable (`.example.com`, `.example.co.uk`) : l'identité est donc partagée entre sous-domaines.

`identify()` rejette les valeurs qui sont techniquement des chaînes mais ne portent aucune identité — `undefined`, `null`, `unknown`, `inconnu`, `0`, `-1`, `NaN`, `ko`, `true`, `false`, `{}`, `[]` et la chaîne vide. Vérifiez ce que produit votre template avant la mise en production :

```typescript
const clientId = document.querySelector<HTMLMetaElement>('meta[name="user-id"]')?.content

// Se protéger des valeurs de repli de templating comme « undefined » ou « 0 »
if (typeof clientId === 'string' && /^[^\s]{2,}$/.test(clientId)) {
  window.reel.identify(clientId)
} else {
  console.warn('Reelevant: no usable identity on this page, tracking stays anonymous')
}
```

## Garanties de livraison

Le tracker envoie chaque événement en `XMLHttpRequest` et applique trois règles à prendre en compte :

| Comportement | Détail |
|--------------|--------|
| **Déduplication** | Les couples `name` + `data` identiques ne sont envoyés qu'une fois par chargement de page. Ajoutez un label discriminant si vous avez besoin d'événements identiques répétés. |
| **File de retry** | Les échecs réseau et les réponses `5xx` sont stockés dans la clé localStorage `rlvt_fail_queue` et réessayés toutes les 60 secondes. |
| **Expiration** | Les événements en file depuis plus de 30 minutes sont abandonnés au lieu d'être réessayés. |

Les événements ne sont pas envoyés sur `beforeunload`. Envoyez-les au moment de l'interaction, pas au départ de l'utilisateur.

## Vérifier une intégration

<Steps>
  <Step title="Envoyer des événements depuis le navigateur">
    Ouvrez votre page, vérifiez que `window.reel.getClientId()` renvoie votre identité de test, puis déclenchez les événements intégrés.
  </Step>
  <Step title="Contrôler les appels réseau">
    Chaque événement est un `POST` vers `https://collector.reelevant.com/collect/{datasourceId}/rlvt` renvoyant `200`. Un `404` signale un `datasourceId` erroné ; un `4xx` avec une Datasource en pause signale une collecte arrêtée.
  </Step>
  <Step title="Contrôler la console">
    Les problèmes de payload sont journalisés côté client avec le préfixe `Reelevant error:` ou `Reelevant warning:`, et l'événement n'est pas envoyé.
  </Step>
  <Step title="Contrôler l'ingestion">
    Les champs rejetés sont signalés dans les [logs de la Datasource](/fr/advanced-guide/datahub/logs). Le collecteur répond toujours `200` : les erreurs d'ingestion ne sont visibles que là.
  </Step>
</Steps>
