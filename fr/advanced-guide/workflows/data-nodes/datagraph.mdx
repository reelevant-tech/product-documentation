## Vue d'ensemble

Le Data Node **Objet Datagraph** exécute la version Live d'un [Objet Datagraph](/fr/advanced-guide/datahub/datagraph/entities) et expose les lignes obtenues aux Nodes suivants. C'est le seul moyen de consommer le modèle Datagraph dans un Workflow.

Contrairement à un Node Datasource, qui lit une seule Datasource, ce Node exécute le SQL joint préparé dans l'Objet. Les filtres, les jointures et le tri vivent donc dans l'Objet, pas dans le Node.

<Warning>
  Le Datagraph est en bêta, et le Node est réservé aux administrateurs techniques. Les autres utilisateurs ne le voient pas dans le menu **Data** de l'éditeur.
</Warning>

## Ajouter le Node

Survolez le bouton **Data** de la barre d'outils de l'éditeur et sélectionnez **Objet Datagraph**. Voir [Data Nodes](/fr/advanced-guide/workflows/data-nodes) pour la procédure générale.

![Menu Data de l'éditeur de Workflow avec l'option Objet Datagraph en bas de la liste](/images/workflows/node-picker-data-datagraph.png)

## Configuration

| Champ | Description |
|-------|-------------|
| **Objet** | Choisissez un Objet dans **Sélectionner un objet publié**. Seuls les Objets disposant d'une version **Live** apparaissent ; un Objet Live unique est présélectionné. |
| **Paramètres de l'objet** | Un champ par paramètre de la définition Live de l'Objet sélectionné. La courte description de chaque paramètre apparaît au-dessus du champ. |

Le message du sélecteur vide est *Aucun objet publié n'est disponible pour le moment.* **Ouvrir l'objet dans Datahub** ouvre l'Objet dans un nouvel onglet, dans le compte courant.

Changer l'Objet sélectionné efface les valeurs déjà saisies, car les noms des paramètres dépendent de sa définition.

<Info>
  Publier une nouvelle version d'Objet qui renomme ou ajoute un paramètre ne met pas à jour les Nodes déjà configurés. Rouvrez chaque Node pour lier les nouveaux paramètres, sinon les valeurs obligatoires manqueront à l'exécution.
</Info>

<Warning>
  Seuls les administrateurs techniques peuvent configurer les nœuds d'interrogation d'objet Datagraph.
</Warning>

<Info>
  Le champ facultatif **Limite de résultats** est masqué par défaut. Il apparaît uniquement si un administrateur technique active **Objet Datagraph : limite de résultats** dans les paramètres des Workflows → onglet **Fonctionnalités**.
</Info>

## Lier les paramètres

Chaque paramètre est lié soit à une valeur statique, soit à une valeur produite en amont dans le Workflow, via le **Variable Picker**. Le contrôle suit le type déclaré et affiche la courte description au-dessus du champ.

| Type de paramètre | Contrôle |
|-------------------|----------|
| `string`, `id` | Valeur texte ou valeur du Workflow |
| `number` | Valeur numérique ou valeur du Workflow |
| `datetime`, `datetime_iso` | Valeur de date ou valeur du Workflow |
| `boolean` | Valeur texte ou valeur du Workflow |

![Champ de paramètre Objet Datagraph avec son type, sa courte description et les valeurs du Workflow disponibles](/images/workflows/node-datagraph-query-parameter.png)

Un paramètre prend une seule valeur. Les valeurs multiples pour un même paramètre ne sont pas prises en charge.

Les paramètres obligatoires doivent être liés. Si un paramètre obligatoire n'a pas de valeur à l'exécution, l'Objet est rejeté avec une erreur de paramètre invalide.

<Info>
  Quand l'Objet déclare un paramètre `client_id` et que le Workflow résout exactement une personne suivie, cet identifiant est utilisé pour `client_id` si vous avez laissé le champ vide. Une valeur liée explicitement est toujours prioritaire.
</Info>

## Sortie

Le Node renvoie une liste de lignes. Chaque ligne contient les colonnes de sortie inférées par l'Objet, avec des valeurs texte, numériques ou vides.

Ces colonnes sont exposées aux Nodes suivants dans le **Variable Picker**, sous le nom de l'Objet, et peuvent alimenter un [Content](/fr/product-guide/contents/overview) ou une [Condition](/fr/advanced-guide/workflows/logic-nodes/conditions).

Le Node affiché sur le canvas porte le nom de l'Objet sélectionné : un Workflow utilisant plusieurs Objets reste lisible.

![Data Node Objet Datagraph sur le canvas du Workflow, affichant le nom de l'Objet sélectionné](/images/workflows/node-datagraph-query-canvas.png)

## Exemple concret

Un Datagraph d'annonces immobilières relie les utilisateurs, les annonces, les recommandations et les prix du marché. L'Objet `listings_matching_a_user_search` déclare un paramètre, `user_id`, et renvoie une ligne par annonce correspondante avec sa référence, sa surface, sa ville et son prix.

Dans le Workflow :

1. Un Node **URL Parameter** capte `user_id` depuis l'appel réalisé par l'outil d'envoi.
2. Un Data Node **Objet Datagraph** sélectionne `listings_matching_a_user_search` et lie `user_id` au paramètre **URL Parameter**. Si elle est activée, définissez la **Limite de résultats** sur 6.
3. Le Content parcourt les lignes renvoyées pour construire un bloc de six annonces.

Comme les jointures vivent dans l'Objet, la même configuration de Node fonctionne pour chaque destinataire, et le modèle peut être corrigé sans toucher au Workflow.

## Points opérationnels

- Si le champ **Limite de résultats** est activé, alignez-le sur ce que le Content affiche. Les lignes récupérées mais jamais affichées coûtent quand même du temps d'exécution.
- Testez l'Objet avec **Run query** dans l'éditeur d'Objet avant de l'ajouter à un Workflow, avec les mêmes valeurs de paramètres.
- Les relations dont le taux de correspondance est faible produisent des résultats partiels. Vérifiez-les dans l'onglet [Relations de la page Schema](/fr/advanced-guide/datahub/datagraph/explorer) avant de mettre en cause le Node.
- Un Objet dont les Datasources sont protégées par des filtres au niveau des lignes ne peut pas être exécuté depuis un Workflow.
